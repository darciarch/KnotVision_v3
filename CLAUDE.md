# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

`img2texcelle` (a Python package, run as `python -m img2texcelle`) converts a finished carpet design image (jpg/png) into an indexed TIFF or BMP for Texcelle (carpet/weaving CAD). Every palette entry is one yarn, and every pixel is one knot/point. So the output must contain only palette colors, with no speckles, no one-pixel noise, and no in-between blend colors at edges. The user judges results by zooming into the output, and they communicate in Turkish.

Every run lives in `data/<name>/` (name = source file name without extension): the source image is **moved** there, and `<name>.tiff` / `<name>.bmp` plus `<name>_palette.txt` are written next to it (with `--part`: `<name>_part.png` + `<name>_part.json` instead of the tiff/bmp, finished later by `python -m img2texcelle.assemble`). A second run on the same image writes `<name>_2.*`, then `_3`, ...; nothing is ever overwritten. `data/` is gitignored.

## The real loom (ground truth)

`data/real_designs/003_200X300_397X50_X/003_200X300_397X50_X.zip` (and the unpacked `.bmp`) holds a real, weave-ready Texcelle design for a 200×300 cm carpet. Everything the tool produces should look like it:

- **Grid**: 793×1501 knots = reed 397 points/m across × 500 rows/m along ("397X50" = 50 rows per 10 cm), ≈198 500 points/m². A knot is 2.52×2.00 mm, **not square**. `--reed 397 --density 500` gives 794×1500.
- **Header**: BMP pels-per-meter = 15630/19685, i.e. Texcelle writes reed/density into the resolution fields as if they were dpi (PIL reads `dpi == (397, 500)`). The tool writes the same (`dpi=(ppm_x, ppm_y)`) for BMP and TIFF.
- **Palette**: index 0 is black and unused; yarns are indices 1..15. The tool reserves index 0 the same way; `<name>_palette.txt` starts at 1.
- **Style**: flat symbolic colors, no shading; pixel art where 21% of all knots lie in 1-knot-wide strokes and 44% of the 10 314 connected components are under 20 knots. So any "thinner than 3 knots is noise" rule destroys the design; the default `--min-area` is 20 mm² worth of knots (4 at 397×500).
- **Source discipline**: the only input is a plain image file (jpg in practice): square pixels, aspect ratio near the carpet's cm ratio, flat-colored (no shadows, gradients, bevels), more pixels than knots in both directions. No other input exists (no Texcelle files, no knot-scaled images). Nothing is stretched by default: `--width` is kept and the height follows the image ratio (the knot grid grows with it; more than 10% off `--height` is an error). `--stretch` fits the image into the given cm size by stretching it up to 10% (more is an error) and prints the distortion. Fewer pixels than knots in either direction is an error. A shaded source turns bevels into same-hue slivers in the output; the only remedy is a flat source.

`img2texcelle.split` writes lossless PNGs to `data/cropped_images/<name>/<name>_<part>.png`, one folder per source image; a later run on the same image adds to that folder with `_2`, `_3`, ... (nothing is ever overwritten) and the source is left where it is. `--keep` is a comma-separated list of part names (default all). The cut is at the geometric centre; an odd side puts its middle pixel row/column into both parts (a warning is printed), so the parts have the same size. `--symmetric` measures the real mirror axis of each cut axis with `symmetry.measure_axis` (the same measurement the pipeline uses, see step 1) and cuts there: each part runs from the axis to its own edge, so nothing is cropped and the parts differ in size when the axis is off centre (fom: top 3392×2400, bottom 3392×2656; a pixel row/column on the axis goes into both parts). An axis with contrast > 0.7 is not trusted: the warning names the best candidate and the `--shift DX,DY` that forces it, and the cut stays at the centre. `--shift DX,DY` sets the axes by hand (`measure_axis` sign convention: the axis is DX/2 px right and DY/2 px down of the centre; fom top/bottom = `--shift 0,-256`).

Tuning flags: `--merge` (delta E for merging auto colors, default 6), `--min-area` (knots; default 20 mm² of knots: 4 at 397×500), `--symmetry` (`auto` / `none` / `lr` / `tb` / `both`, default `auto`: `auto` takes an axis with contrast < 0.4, names one between 0.4 and 0.7 in a warning with the flag that forces it, `lr` / `tb` / `both` take the measured axis below 0.9 and the centre above with a warning; one half of a mirror-symmetric design is converted and mirrored onto the other, so opposite motifs are identical; halves that match everywhere are also decided from both together), `--no-average` (never decide an axis from both halves: only the kept part plus a pad is converted, faster, the output changes), `--piece t/b/l/r/tl/tr/bl/br` (the image is that piece of a mirror-symmetric carpet: t/b = the top/bottom half, mirrored on the top/bottom axis, l/r = the left/right half, mirrored on the left/right axis, tl/tr/bl/br = a quarter, mirrored on both; the name is in the image's own orientation, the image is never given rotated; `--width`/`--height` are still the whole carpet's cm, and the piece must have the piece's cm ratio: the top half of 200×300 is 200×150 = 4:3, the left half 100×300 = 1:3, a quarter 100×150 = 2:3; mirroring gives the carpet ratio back and the ratio check runs on the full image; the knot grid is the same as for the whole image; the axis that is not mirrored is neither measured nor used, so a half of a both-ways symmetric carpet converts 51% of the grid and a quarter 27%: give the quarter; every axis is copy-only, `--no-average` is implied; together with a `--symmetry` other than `auto` it is an error), `--part` (write the kept part `<name>_part.png` + `<name>_part.json` instead of the tiff/bmp, for editing; `python -m img2texcelle.assemble <name>_part.png [--format bmp]` mirrors it into `<name>[_N].tiff/bmp` + palette, matching pixels by RGB so an editor's RGB save or palette reorder is fine; a color not in the palette, the reserved black or a wrong size is an error), `--stretch` (fit the design into the given cm size by stretching it, up to 10%; default: `--width` is kept and the height follows the image), `--format` (`tiff` / `bmp`, default `tiff`), `--debug-dir` (writes `regions.png`, the part's label map before cleanup). `--width`, `--height`, `--reed` and `--density` are required.

Only the kept part is converted (see pipeline step 1), so the run time follows the converted share of the grid. fom (3392×5312 at 397×500, 8 yarns), measured 2026-09-17 one run at a time: whole image 178 s (`unmix` 63 s + `unmix_thin_blends` 78 s = 84% of it, `smooth_chroma` 11 s, vote 12 s), `--symmetry both` 91 s (51% converted: the left/right axis is averaged, so both halves are needed; the top/bottom axis is copy-only), `--symmetry both --no-average` 47 s (27%); `assemble` takes a second. `--piece` follows the same rule at the piece's pixel density (fom's bottom-left quarter 1696×2656 with `--piece bl`: 44 s; the bottom half with `--piece b`: 97 s); a piece drawn at the whole image's pixel count costs ~4× (the quarter at 3392×5312: 201 s). The real design's render (3388×5082, 15 yarns) takes 275 s whole, and both axes are averaged so 100% is converted; `--no-average` converts 27%.

## Pipeline (`pipeline.convert`)

The source is finer than the knot grid, so every knot takes the yarn covering most of its area. The order matters:

1. **Orientation, symmetry, carpet size, scale, part** (`grid.rotate_to_carpet`, `symmetry.find_axes`, `symmetry.mirror_halves`, `grid.fit_carpet`, `grid.source_scale`, `symmetry.part_region`). If the image and the carpet have different orientations, rotate the image 90°. `symmetry.measure_axis` (shared with `img2texcelle.split --symmetric`) finds the mirror axis of each direction: on the greyscale reduced up to 8× (≥ 128 px on the short side) every axis position within ±25% of the size is tried, comparing only the rows within ±15% of the size around the candidate axis (the rows that meet at the cut; nothing wraps around), then refined at full resolution. Two numbers come out. `contrast` = error at the best axis / best error more than 32 px away (0 = perfect mirror, 1 = flat curve, no axis); an axis counts when it is below 0.7 (measured 2026-09-17: real design 0.00, WhatsApp scan 0.16, fom 0.12 left/right and **0.57 top/bottom** with its medallion 128 px above the centre, the fom quarter images with no symmetry 0.79–0.99). Three thresholds: `auto` takes an axis below `AXIS_CONTRAST_AUTO` 0.4; between 0.4 and `AXIS_CONTRAST` 0.7 (fom top/bottom) it is not used but a warning names the candidate, its contrast and the `--symmetry lr/tb/both` that forces it; `lr` / `tb` / `both` use the measured position below `AXIS_CONTRAST_FORCED` 0.9 and the centre above it with a warning. Without the separate forced limit `--symmetry both` on fom (0.57) would fall back to the centre and the off-centre logic would never run; fom is therefore always run with `--symmetry both`. `img2texcelle.split --symmetric` keeps 0.7. `match` = whole-image error at that axis / error of a 32 px shift (the old whole-image criterion): below 0.35 the halves match everywhere (real design 0.00–0.02, fom left/right 0.14), otherwise only near the axis (fom top/bottom 1.12: the crowns and corner motifs were drawn 100+ px from their mirror positions). Whole-image matching alone could never find the fom axis, which is why the first version of this step failed on it. An off-centre axis splits the image into two halves of different size (`half_sizes`; fom: 2400 rows above, 2656 below); one is kept and the other replaced by its mirror (`mirror_half`, `mirror_halves`), so the axis becomes the image centre and nothing is cropped or stretched at this point. Without `--stretch` the larger half is kept (fom: 3392×5312 from the bottom half); with `--stretch` the half whose mirrored image is closest to the carpet ratio (fom: still the bottom half, 4.4% distortion against 6.0% for the top half; the alternative is printed). An axis at the centre leaves the image alone, so both halves keep their evidence. The kept side is what `mirror_copy` copies from after cleanup, which makes opposite motifs bit-identical (without it an output matched its own mirror on only 93.8% of the knots); when the halves also match everywhere (`match` < 0.35) the knot-grid coverage maps are first averaged with their mirror (`mirror_average`), never when they match only near the axis (that would blend the two different crowns into ghosts). Caveat: a motif present on one side only is lost to the copy; use `--symmetry none` or force only the right axis. `--no-average` makes every axis copy-only (`find_axes(..., average=False)`): the output then comes from the kept half alone (fom: 6.4% of the knots differ from the averaged output, the real design's render 0.5%), which is what makes the part below small. A copy-only axis at the centre also gets `mirror_half` (the other half replaced by the reflection of the kept one), so the pad below is reflected pixels and never the discarded half. Then `fit_carpet` decides the carpet size. Default (no `--stretch`): nothing is stretched, `--width` is kept and the height follows the image ratio, the knot grid grows or shrinks with it and the new size is printed as a banner (`*** CARPET 200 x 313.2 cm, KNOT GRID 794 x 1566 ***`; fom, 0% distortion); a height more than 10% off `--height` is an error that points to `--stretch`. With `--stretch` the given size is used and the image is area-averaged onto the knot grid in step 4 (a stretch); the distortion (`grid.distortion`: the larger scale factor over the smaller, minus 1) is printed and more than 10% is an error (fom: 4.4%, `--symmetry lr --stretch`: 0.6%). `compute_pixels` gives the knot grid plus the points per meter written into the header. `source_scale`: the source must have more pixels than knots in both directions, otherwise an error; `scale = sqrt(sx*sy)` is the mixing reach of step 3. Finally `part_region` picks the knots to convert: along a copy-only axis the kept half (an odd grid keeps its middle knot, centred on the axis, in the part: 79 knots → a 40-knot part; the loom's point count is never changed) plus `PAD_KNOTS` = 20 knots beyond the axis, the reach of `straighten_runs` (runs ≥ 15, window 9), `directional_mean` and `remove_islands`; along an averaged axis the whole extent (the other half is evidence); no axis: everything. The part without the pad is the output part. The region's source pixels are cut out (`pipeline.source_crop`, rounded outwards to whole pixels; `vote.resize_alpha` is told the crop origin and the whole grid's scale, so every knot gets exactly the value it has in the whole image) and everything below runs on the crop only (fom: 794×803 of 794×1566 knots = 51%, with `--no-average` 417×803 = 27%). With `--piece` the order is: `symmetry.mirror_piece` first (the piece stays at its own position and is reflected across its axis or axes, the edge row/column doubled so the axis lies on a pixel boundary at the exact centre: a half becomes 2w×h or w×2h, a quarter 2w×2h; the rotation is decided on this full image), then `rotate_to_carpet`; if it rotated, the piece name is mapped with `grid.rotate_piece` (`ROTATE_90` is counter-clockwise, the top edge becomes the left edge: t→l→b→r→t, tl→bl→br→tr→tl; the console says `rotated 90 deg to 600x400, piece t -> l`); then `symmetry.centre_axes` instead of `find_axes`: the mirrored axis or axes at the centre, copy-only, nothing measured, and the kept side is the piece's own side (`mirror_halves` takes it through its `sides` argument instead of choosing); the rest is unchanged (`mirror_half` is a no-op on the symmetric image, `fit_carpet`, `source_scale`, `part_region`, `source_crop`, `mirror_copy`). The console line is `piece br: image 1696x2656 mirrored to 3392x5312, both axes at the centre, copy only` / `piece t: image 400x300 mirrored to 400x600, top/bottom axis at the centre, copy only`; the height error and the CARPET banner name the piece and the full size together. The scale follows the source: a piece drawn at the same pixel count as a whole image doubles the scale on the mirrored axis (fom: sx 4.27 → 8.5 with sy 3.39), so the anisotropy grows and `reach = ceil(sqrt(sx*sy))` stays ~1.4× short on that axis; accepted, the output is still symmetric. `img2texcelle.split` output can be given to `--piece` (a `--symmetric` / `--shift` cut is the right piece for an off-centre axis), but on an odd side `split` puts the middle row/column into both parts and `mirror_piece` doubles it, so the full image is 1 px larger than the original. A knot of the part can differ from the whole-image conversion only where a structure crosses the pad (a run straddling the axis longer than 40 knots, a thin blend strip attached to a wide area 85+ px away): measured 2026-09-17 on fom and on the real design's render, zero knots differ (see Verification).
2. **Palette** (`color.auto_palette`, unless `--palette`). k-means in Lab on the part's crop, fit only on `flat_mask` pixels (low 3×3 contrast), so edge blends never become palette entries. Near-duplicate clusters are merged (`--merge`) and tiny ones dropped. At loom quality always pass `--palette`: yarns used only for 1-knot lines and yarns within `--merge` of each other never enter an auto palette (on the real design with `--colors 15` less than three quarters of the knots got the right yarn).
3. **Coverage unmixing** (`color.smooth_chroma` + `unmix.unmix` + `unmix.unmix_thin_blends`). a/b are smoothed with a joint bilateral filter guided by L (JPEG chroma is half resolution). Then every pixel is explained as one pure yarn color or a mix of two (the Lab segment passing closest), giving coverage fractions `alpha` per color; pure wins unless a mix is better by 3 ΔE. `unmix(..., reach=ceil(scale))` only allows a pair where both colors occur as nearest pure color within `reach` px: without this, with 15 yarns, a slightly desaturated magenta line was explained as 30% purple + 70% orange and whole lines changed yarn. `unmix_thin_blends` then unmixes thin strips of an in-between color (grey lies between blue and cream) that are not attached to a wide area of it into the two colors it blends; without it blurred 1-knot lines look like an in-between color and stroke errors nearly double at a non-integer source scale.
4. **Coverage vote** (`vote.vote_knots`). `alpha` is resized to the region's knots with `resize_alpha`, a bit-exact numpy copy of PIL's BOX resize that takes whole-grid knot indices (an area average of pixel centres; bilinear blurred 2 px lines into their 2 px gaps; PIL itself takes the resize box in single precision, and a fractional box end flipped exact 50/50 ties on the real design's dashed border), so every knot holds the fraction of its area covered by each yarn ("soft" coverage), and argmax'ed. Soft coverage beats the majority of one-hot pixel labels ("hard"), most at a non-integer source scale. Then `straighten_runs`: a straight band edge or a thin line that straddles a knot row covers every knot on that row by about half, so the per-knot argmax flips with JPEG noise and a straight edge came out jagged (the top border band of one source started on row 1 in 440 columns and row 2 in 254). Knots whose `directional_mean` (mean along the orientation of least variation) is undecided (max < 0.6, own coverage < 0.85 so clean dots and strokes are never touched) are grouped into runs along that orientation, and every run of ≥ 15 knots takes the majority of the *hard* coverage over the run (the soft mean ties on a line straddling two rows evenly). Shorter runs (min_run 9) start eating real detail on the real design.
5. **Cleanup** (`cleanup.remove_islands` on the region, then the pad is dropped). Components smaller than `--min-area` take the most common color in their 1-knot ring, repeated until nothing changes (on the real design `remove_islands(4)` touches only 494 of 1.19 M knots). Don't add a mode filter or bump smoothing here: on a real loom grid the corner knot of every 1-knot diagonal staircase has 3 foreign neighbours, and `smooth_bumps` erased 3% of the real design.
6. **Output** (`pipeline.assemble_full` + `output.save_indexed`, `write_palette_txt`; with `--part` `output.save_part`). The part is placed on the full knot grid and `mirror_copy` mirrors it across every taken axis (opposite motifs bit-identical). 8-bit `P` mode TIFF or BMP, uncompressed, index 0 reserved (black, unused) and yarns from 1, resolution fields = points per meter, plus `<name>_palette.txt` with one line per yarn: `index\tR\tG\tB\t#RRGGBB`. Keep both formats stable, because Texcelle consumes them. `--part` instead writes the part as the same kind of 8-bit `P` PNG (`<name>_part.png`) plus `<name>_part.json` (format `img2texcelle-part` version 1: source name, rotation, carpet cm, stretch and distortion, reed/density/ppm, full grid, the part's position and size on it, pad, min area, per axis the kept side / averaged / shift / position in the source, the palette as hex) and the palette text, then stops. `python -m img2texcelle.assemble <name>_part.png` (`output.load_part` + `assemble_full`) reads both, matches pixels by RGB (an editor may save RGB or reorder the palette; a color not in the palette, the reserved black unless a yarn is black, or a size other than the JSON's is an error listing the pixels), mirrors and writes `<name>[_N].tiff/bmp` + palette into the same folder, never overwriting; the source image is not needed. `--symmetry none --part` writes the whole grid with no axes.

## Verification

There is a small pytest suite (synthetic design end to end, aspect and scale rules, folder rules), but the real defects are visual and numeric:

- **Look at the output**: crop the same region from the source (resized to the knot grid with BOX) and from the output, scale both up with NEAREST, compare side by side. Check a corner, the medallion and the top border band (straightness), and that the left and right halves are identical. Also check that the output has no connected components smaller than `--min-area` (8-connectivity, `scipy.ndimage.label`).
- **Off-centre axis** (references made 2026-09-17; all re-verified pixel-identical after the part conversion): `data/fomggggggbro/fomggggggbro.jpg` (3392×5056, medallion 128 px above the centre) with `--width 200 --height 300 --reed 397 --density 500 --palette` from its `_6_palette.txt` `--format bmp --symmetry both` must print the left/right axis at the centre (contrast 0.12, average + copy), the top/bottom axis at row 2399.5 (contrast 0.57, copy only), `bottom half (2656 rows) kept and mirrored onto the top (2400 rows): image 3392x5312 (the larger half)`, the banner `*** CARPET 200 x 313.2 cm, KNOT GRID 794 x 1566 ***` (4.4% taller, nothing stretched), `part: knots [0, 397) x [783, 1566) of 794 x 1566 (397 x 783); converting 794 x 803 knots = 51% of the grid` and give an output pixel-identical to `fomggggggbro_10.bmp` (794×1566): mirror-symmetric both ways with no ghost motifs at the crowns. Without `--symmetry both` the top/bottom axis is only named (`warning: top/bottom mirror axis unclear, not used (... contrast 0.57 >= 0.4); force it with --symmetry tb (or both)`) and the output is left/right symmetric only. ## Things tried and rejected

- Unsharp mask after LANCZOS upscaling: creates fake outlines along edges.
- RGB resize followed by quantization: gives fringe pixels of a third color between two yarns.
- Per-pixel nearest-color labeling + island removal: thin lines break into beads.
- Ridge/skeleton line detection (the old path B for coarse sources) run at source resolution and rasterized onto the knots: far worse than the coverage vote on the real design; it fattens 1-knot lines in dense pixel art and adds highlight specks on shaded sources. Removed on 2026-09-16 together with the outline-color logic and `scikit-image`.
- A per-knot "coherent vote" (replace ambiguous knots by the 9-knot directional mean): loses knots on the real design, because straddling 1-knot lines tie in both rows.
- Gaussian smoothing of the source coverage: blurs 2 px lines into their gaps.
- `smooth_bumps` / mode filters on the knot grid: erase the corners of 1-knot diagonal staircases (3% of the real design).
- Averaging the four quadrants of a both-ways symmetric design does not always pick the best one, but exact symmetry is what the weaver notices first.
- Source-specific knobs `--specks` (repaint same-hue slivers of shaded sources; erased ~1% of real same-hue details), `--denoise` (median filter; breaks 1 px lines), `--fit crop` / `--fit stretch`, `--points`, `--no-rotate`, `--grid` and the knot-grid-ratio acceptance in the aspect check: removed on 2026-09-17, the input spec above replaces them.
- Cropping an off-centre mirror axis to the centre (`crop_to_axis`): threw away part of the larger half and changed the ratio (fom 3392×4800, 6.0% stretch). Replaced on 2026-09-17 by keeping one half and mirroring it (`mirror_halves`) plus `--stretch`.
- Rounding an odd knot grid to an even one so the axis falls on a knot boundary (considered with the part conversion, 2026-09-17): a 100 cm carpet at reed 397 has 397 points and the weaver expects that count. Instead the middle knot, centred on the axis, belongs to the part and `mirror_copy` leaves it alone.
- Converting the whole image and mirroring at the end (until 2026-09-17): the discarded half's work was thrown away and the kept part could not be seen or edited before mirroring. Now only the part plus a pad is converted (`part_region`), `--part` writes it and `img2texcelle.assemble` mirrors it.
